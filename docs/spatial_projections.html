Spatial Model Visualization: Scaling Methane Flux in Space

From flux density to emissions

In the Random Forest and Sensitivity Analysis workshops, we built and stress-tested a methane flux model. In this final workshop, we project that same model across Connecticut and turn gridded flux predictions into a methane emissions budget.

The key idea is a unit conversion:

methane flux density x inundated area = methane emissions

Our random forest predicts methane flux as g C m-2 month-1, a rate per square meter. A map of predicted flux is not yet an emissions budget. To estimate emissions, we multiply by the area where methane-producing wetlands are actually inundated.

That is where the Wetland Area and Dynamics for Methane Modeling (WAD2M) product comes in. WAD2M provides monthly inundated-wetland fractions on a global 0.25 degree grid (Zhang et al. 2021). Version 2.0 covers 2000–2020. The NASA UpCH4 methane product uses the same strategy we use here: predict a wetland flux everywhere, then weight it by the WAD2M wetland fraction before converting to emissions.

Useful references:

  • WAD2M paper: Zhang et al. 2021, Earth System Science Data
  • WAD2M data: Zenodo record
  • Example methane upscaling product using WAD2M: NASA Open Data Portal, UpCH4
WarningData dependencies
  • data/products/random_forest_model.RDATA: the final model saved by random_forest.qmd (also created by sensitivity.qmd).
  • data/products/era5_tmean_monthly.tif: ERA5 temperature saved in data_integration.qmd.
  • data/products/modis_evi_ct_2018.tif: monthly 2018 MODIS EVI for Connecticut.
  • data/products/wad2m_fw_ct_2000-2020.tif: WAD2M v2.0 monthly inundated fraction, cropped to Connecticut.

To project this model in space, every predictor needs a value in every grid cell:

Model variable Meaning Unit or class Spatial source
TA_F Monthly mean air temperature degrees C ERA5
EVI Monthly enhanced vegetation index unitless (−1 to 1) MODIS
IGBP_model Ecosystem class factor: CRO, EBF, ENF, GRA, Other, WET set to WET

The prediction has units of g C m-2 month-1.

NoteWhy set every cell to WET?

We are not asking what methane flux a forest or a cornfield produces. We are asking how much methane the wetlands in each grid cell would emit. So we predict a wetland flux everywhere (IGBP_model = "WET"), then let WAD2M decide how much of each cell is actually inundated wetland. Upland cells end up with an inundated fraction near zero, so they contribute almost nothing to the budget.

This is the same logic used in global wetland methane products. It also avoids a mismatch: our model’s ecosystem classes come from tower sites, while MODIS land cover is mapped at 5 km and rarely labels Connecticut’s small, scattered wetlands as WET.

NoteWhat to look for: predictor layers
  • Seasonality. Temperature and EVI should both peak in summer. January EVI near zero (or slightly negative under snow) is expected.
  • Spatial pattern. Temperature is smooth because ERA5 is coarse (about 25 km). EVI shows more detail: urban areas and the coast are lower, and forested uplands are higher.
  • Training domain. Compare these ranges with the training data in the next chunk. The model can only learn from conditions in the training data.

4. Predict monthly flux density

Build the predictor stack for one month. IGBP_model is passed as a constant with the same factor levels as the training data. randomForest refuses to predict if the levels don’t match.

wetland_class <- data.frame(
  IGBP_model = factor("WET", levels = levels(train$IGBP_model))
)

predict_month <- function(i) {
  stack <- c(ta_f[[i]], evi[[i]])
  names(stack) <- c("TA_F", "EVI")
  terra::predict(stack, fch4_rf, const = wetland_class, na.rm = TRUE)
}

flux_jul <- predict_month(7)
plot(flux_jul, main = "July wetland methane flux (g C m-2 month-1)")

Predict all 12 months:

flux <- rast(lapply(1:12, predict_month))
names(flux) <- month.abb
units(flux) <- "g C m-2 month-1"

plot(flux)
NoteWhat to look for: flux density maps
  • These maps show the flux per square meter of wetland, not per square meter of land. A high value does not mean a cell emits a lot. It means the wetlands there would emit a lot if present.
  • Summer months should be highest, driven by temperature and greenness. Compare the seasonal range with the one-at-a-time sensitivity curves from last week.
  • Spatial differences within a month are small because temperature varies smoothly and EVI has a modest effect. Most of the spatial pattern in emissions will come from WAD2M.

5. Where are wetlands inundated? WAD2M

WAD2M gives the fraction of each grid cell that is inundated wetland in each month:

  • 0 means no inundated wetland in the cell.
  • 0.10 means 10% of the cell is inundated wetland.
  • 1 means the whole cell is inundated wetland.

WAD2M excludes permanent open water such as lakes, rivers, and the ocean, so it isolates vegetated wetlands, which are the methane source our model describes.

Load the Connecticut WAD2M series. The layer names are YYYY-MM.

wad2m_all <- rast("data/products/wad2m_fw_ct_2000-2020.tif")
range(names(wad2m_all))
[1] "2000-01" "2020-12"

WAD2M leaves some cells empty (NA) in winter, where snow and ice prevent mapping inundation. To fill those gaps, first build a monthly climatology: the average January across 2000–2020, the average February, and so on, ignoring missing values.

wad2m_month <- as.integer(substr(names(wad2m_all), 6, 7))

wad2m_climatology <- tapp(wad2m_all, index = wad2m_month, fun = mean, na.rm = TRUE)
names(wad2m_climatology) <- month.abb

Select 2018, fill winter gaps with the climatology (cover() replaces NA cells only), then put it on the prediction grid:

to_ct_grid <- function(r) {
  r %>%
    resample(ct_grid, method = "bilinear") %>%
    clamp(lower = 0, upper = 1, values = TRUE) %>%
    mask(ct_grid)
}

wad2m_2018 <- wad2m_all[[grepl("^2018", names(wad2m_all))]]

wad2m <- cover(wad2m_2018, wad2m_climatology) %>% to_ct_grid()
climatology_ct <- to_ct_grid(wad2m_climatology)
names(wad2m) <- names(climatology_ct) <- month.abb

plot(wad2m[[c(1, 4, 7, 10)]])
tibble(month = month.abb,
       fraction_2018 = global(wad2m, "mean", na.rm = TRUE)[, 1],
       fraction_climatology = global(climatology_ct, "mean", na.rm = TRUE)[, 1])

NoteWhat to look for: WAD2M
  • Where. Higher fractions should follow river valleys (for example, the Connecticut River), coastal marshes, and low-lying terrain. Most upland cells are near zero.
  • When. Inundated area is largest in winter and spring, when evapotranspiration is low and snowmelt arrives, and smallest in late summer. That is the opposite of the flux-density cycle, so the two partly cancel in the budget.
  • 2018 vs. average. Compare fraction_2018 with fraction_climatology to see whether 2018 was a wet or dry year for wetlands.
  • Resolution. WAD2M is 0.25 degrees (about 25 km). Resampling to 5 km makes smoother maps but adds no new information about where individual wetlands are.
NoteIf your target year is not available

WAD2M v2.0 ends in 2020. If your final project needs a later year, use climatology_ct in place of wad2m. It keeps the seasonal cycle of wetland area, even though it can’t capture the conditions of that specific year. Say so in your methods. For example: “Because WAD2M was unavailable for the target year, monthly inundation fractions were estimated as the mean WAD2M fraction for each calendar month across 2000–2020.”

6. Convert flux density to emissions

Keep units visible as you work:

Quantity Calculation Unit
flux density random forest prediction g C m-2 month-1
cell area cellSize() m2
inundated area cell area x WAD2M fraction m2
monthly emissions flux density x inundated area g C month-1
annual emissions sum of months / 1e12 Tg C year-1
annual emissions Tg C x 16 / 12 Tg CH4 year-1

Calculate cell area and monthly inundated area:

cell_area_m2 <- cellSize(ct_grid, unit = "m") %>% mask(ct_grid)

inundated_area_m2 <- wad2m * cell_area_m2

Convert flux density to emissions, then sum to an annual map:

emissions_g_c <- flux * inundated_area_m2
names(emissions_g_c) <- month.abb

annual_tg_ch4 <- sum(emissions_g_c) / 1e12 * (16 / 12)
names(annual_tg_ch4) <- "annual_tg_ch4"

plot(annual_tg_ch4, main = "Annual wetland methane emissions (Tg CH4 per cell)")

Tg CH4 = Tg C x 16 / 12 because methane has a molecular mass of 16 and carbon has an atomic mass of 12.

NoteWhat to look for: emissions map

Compare this map with the flux-density maps. The emission hotspots should follow the WAD2M wetland pattern, not the flux pattern. That shows that wetland area, not flux density, controls where methane is emitted at this scale.

NoteHow to interpret the monthly budget
  • Emissions = flux density x inundated area, so the emissions curve is a compromise between the two other panels.
  • If emissions peak in summer, flux density is driving the budget. If the peak shifts toward spring, inundated area matters more.
  • Ask how much of the annual total comes from the warmest three months. That tells you how much the budget depends on summer temperature, where the sensitivity analysis showed the model is most responsive.

8. Why WAD2M scaling matters

Compare the WAD2M-scaled budget with a naive budget that treats every land cell as 100% wetland:

naive_tg_ch4 <- global(sum(flux * cell_area_m2), "sum", na.rm = TRUE)[1, 1] / 1e12 * (16 / 12)

comparison_budget <- tibble(
  method = c("100% of each land cell", "WAD2M inundated fraction"),
  annual_tg_ch4 = c(naive_tg_ch4, annual_budget_tg_ch4)
) %>%
  mutate(percent_of_naive = 100 * annual_tg_ch4 / first(annual_tg_ch4))

comparison_budget
# A tibble: 2 × 3
  method                   annual_tg_ch4 percent_of_naive
  <chr>                            <dbl>            <dbl>
1 100% of each land cell          0.671             100  
2 WAD2M inundated fraction        0.0843             12.6
NoteHow to interpret the comparison

percent_of_naive is roughly the average inundated fraction, weighted by flux. A naive budget assumes the whole state is a wetland and overestimates emissions by about 1 / (inundated fraction). This is the most common mistake when scaling tower fluxes to regions.

9. Inundation-area uncertainty

Wetland area is often the largest source of uncertainty in methane budgets. How much does the budget change if inundation is 50% lower or higher than WAD2M, or if we use the 2000–2020 climatology instead of 2018?

budget_from_fraction <- function(fraction) {
  fraction <- clamp(fraction, lower = 0, upper = 1, values = TRUE)
  global(sum(flux * fraction * cell_area_m2), "sum", na.rm = TRUE)[1, 1] / 1e12 * (16 / 12)
}

budget_uncertainty <- tibble(
  scenario = c("WAD2M x 0.5", "WAD2M 2018", "WAD2M climatology", "WAD2M x 1.5"),
  annual_tg_ch4 = c(budget_from_fraction(wad2m * 0.5),
                    budget_from_fraction(wad2m),
                    budget_from_fraction(climatology_ct),
                    budget_from_fraction(wad2m * 1.5))
)

budget_uncertainty

NoteHow to interpret the uncertainty test
  • Because emissions = flux x area, the budget scales linearly with inundated area: ±50% area gives ±50% emissions (unless clamping at 1 matters).
  • The climatology bar shows how unusual 2018 was compared with an average year. If the difference is small, a climatology is a reasonable substitute for a missing year.
  • This isolates only one source of uncertainty. A full analysis would also include model error (test RMSE), predictor-raster error, and the choice to treat all inundated area as WET.

extract_monthly <- function(r, value_name) {
  terra::extract(r, yale_myers, ID = FALSE) %>%
    pivot_longer(everything(), names_to = "month", values_to = value_name)

yale_myers_monthly <- extract_monthly(flux, "flux_g_c_m2") %>%

Appendix: how the provided layers were made

These steps were run once to create the provided files. You only need them if you want a different region or year.

WAD2M. Download WAD2M_wetlands_2000-2020_025deg_Ver2.0.nc.zip from the Zenodo record (about 275 MB, 1.9 GB unzipped), then:

wad2m_global <- rast("WAD2M_wetlands_2000-2020_025deg_Ver2.0.nc")   # variable Fw
wad2m_ct <- crop(wad2m_global, ext(-75, -70.5, 40, 43))
names(wad2m_ct) <- format(time(wad2m_ct), "%Y-%m")
writeRaster(wad2m_ct, "data/products/wad2m_fw_ct_2000-2020.tif", overwrite = TRUE)

EVI. The model was trained on MODIS EVI (scaled −1 to 1). The Connecticut layers were built from MODIS Terra MOD13A1 v061 (500 m, 16-day) for tile h12v04, 2018. Composites were assigned to the month of their midpoint, averaged within each month after removing fill values (−3000) and applying the 0.0001 scale factor, then aggregated to the 0.05 degree grid. An AppEEARS area request for MOD13A3 (monthly, 1 km) over your region is an equivalent and simpler route:

evi_files <- list.files("path/to/MOD13A1_EVI_2018", pattern = "EVI.tif$", full.names = TRUE)
doy <- as.integer(str_extract(basename(evi_files), "(?<=A2018)\\d{3}"))
evi_month <- as.integer(format(as.Date(doy + 7, origin = "2017-12-31"), "%m"))

evi_ct <- rast(lapply(1:12, function(m) {
  r <- rast(evi_files[evi_month == m])
  r[r == -3000] <- NA
  project(mean(r * 0.0001, na.rm = TRUE), ct_grid, method = "average")
}))
names(evi_ct) <- sprintf("EVI_m%02d", 1:12)
writeRaster(evi_ct, "data/products/modis_evi_ct_2018.tif", overwrite = TRUE)
